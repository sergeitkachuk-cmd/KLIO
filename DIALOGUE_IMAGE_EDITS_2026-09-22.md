# Доработка изображений и режимы диалога — 22 сентября 2026

Ветка сайта: `codex/dialogue-shell-v2`, только тестовый стенд.
Маркер: `X-Klio-UI-Release: 2026-09-22-dialogue-image-edits-v5`.

## Прозрачные края после добавления логотипа

После обновления Render владелец получил результат с добавленным логотипом,
но с исчезающими краями. Проверка его `klio-image.png` (1536×1024, RGBA) выявила
80 544 полностью прозрачных пикселя, 1 492 320 частично прозрачных, 0 полностью
непрозрачных. Тёмные края в просмотрщике — отображение прозрачности, не просто
затемнение. Содержимое фото за прозрачными краями этим файлом не восстанавливается.

В v5 `createImageFromSource` для доработки по умолчанию явно передаёт
`background: "opaque"` через JSON relay и multipart Image API. Раньше параметр
вообще не передавался, оставляя выбор фона модели. Явно переданный вызывающим кодом
`background` сохраняется; режим визуального референса не меняется.
Инструкция сохраняет края/углы и запрещает перенос прозрачности логотипа на фото,
расчистку места и незапрошенное оформление. При отключённом профиле убрано
противоречивое указание «Создай изображение» из задания на доработку.

Уже обновлённый Render поддерживает `background`; новый образ для этой правки
не требуется. Нужно обновить только тестовый стенд. Повторять добавление логотипа
следует от оригинальной карточки, до неудачной правки. Проверка передачи параметра
не заменяет визуальную оценку новой реальной генерации.

## Уточнение после ошибки на стенде

22 сентября повторная проверка показала: Timeweb уже отдаёт `image-edits-v3`,
а `https://klio-telegram-relay.onrender.com/health` возвращает только `ready:true`.
Такой relay не подтверждает поддержку двух входных изображений. Запрос с исходником
и логотипом останавливается перед вызовом `/generate`. Присланный файл
`stand-app-logs-4603-2026-09-22T09_04_53.730Z.txt` подтвердил эту причину обеих
попыток (`dialogue reply failed`, строки 1911 и 1923). Позднейший обрыв интернета
не объясняет серверный отказ: AI-запрос не был отправлен.

В v4 причина отсутствия поддержки relay имеет отдельный тип ошибки и показывается
в диалоге вместе с подтверждением сохранения сообщения/исходника и возврата лимита.
Сырые ошибки провайдера и хранилища не раскрываются. HTTP-сбой `/health` не выдаётся
за необходимость обновления. Это улучшение диагностики, не замена обновлению Render.

## Реализовано

- Переключатель Диалоговый / Профессиональный имеет согласованные фон и текст
  для светлой, тёмной и начальной темы без `data-theme`.
- Явные вопросы, объяснения, обсуждение и благодарность переводят оставшийся
  режим генерации в общение. Это консервативные локальные правила, не отдельный
  AI-классификатор; неоднозначную формулировку лучше уточнить. «Ещё вариант»,
  обычное описание и прямые правки не сбрасывают режим. Явно выбранное
  «Общение» и действия на карточках имеют приоритет.
- «Доработать» под изображением прикрепляет именно выбранный исходник.
  Карусель позволяет выбрать отдельный слайд. Кнопка не запускает генерацию.
  В режиме изображения можно загрузить PNG/JPEG/WEBP до 8 МБ и выбрать
  «Доработать исходник» либо «Взять за референс».
- «Добавь на это изображение наш логотип» использует последний однозначный
  исходник из текущего диалога и файл логотипа выбранного бренда. У карусели
  нужно выбрать слайд. При отсутствии исходника/логотипа запрос отклоняется
  до списания. AI не должен придумывать знак. Обычные новые варианты по-прежнему
  используют контекст запросов, без неявной привязки к старой сцене.
- Источник сохраняется с черновиком, восстанавливается после сбоя, разделён
  между диалогами и бизнесами. В истории есть миниатюра исходника. Доработка
  создаёт отдельный материал и карточку, сохраняя оригинал.
- Сервер читает только принадлежащий пользователю ключ из собственного S3;
  произвольные URL не скачиваются. Изображение идёт первым входом, логотип —
  вторым. Для правки передаётся `size=auto`. AI-редактирование может менять
  отдельные детали; точное сохранение пикселей этим интерфейсом не обещается.
- Списание по-прежнему одно на результат, повтор запроса не списывает снова,
  сбой возвращает лимит. Просроченный worker не сохраняет материал после возврата.

## Render

Рабочий сервис имеет отдельную ветку `codex/klio-image-service`; его код также
обслуживает `/responses` и Telegram. Нельзя заменять его старой копией server.mjs
из ветки сайта. Точечное совместимое обновление подготовлено отдельно:

`fd4f446dfd5e17b2bf1ae8489d44225d51b45f4d`.

Контейнер:
`ghcr.io/sergeitkachuk-cmd/klio-relay:fd4f446dfd5e17b2bf1ae8489d44225d51b45f4d`

Сборка и проверки контейнера прошли:
https://github.com/sergeitkachuk-cmd/KLIO/actions/runs/35705196862

Контейнер опубликован, но применение образа в Render этим фактом не подтверждается.
После обновления `/health` должен возвращать `ready:true, maxImageInputs:2`.
Проверка возможностей перед запросом с двумя входами защищает от старого relay,
который иначе молча проигнорировал бы поле `images` и создал другую картинку.
Функции текста/Telegram и их настройки в отдельной ветке сохранены; обновление
не отправляет публикации. Секреты, диск и команду запуска менять не требуется.
