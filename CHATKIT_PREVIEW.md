# Тестовый стенд ChatKit в существующей PostgreSQL

Ветка: `codex/dialogue-shell-v2`. Стенд:
`https://sergeitkachuk-cmd-klio-stand-682f.twc1.net`.

Стенд может использовать тот же сервер и ту же базу PostgreSQL, но отдельные
таблицы в схеме `klio_preview_chatkit`. Новая управляемая база не создаётся.
Это логическое разделение: ресурсы сервера и права пользователя подключения
остаются общими. Доступ к `CREATE SCHEMA` требует права `CREATE` на базу.

## Настройка Timeweb

Сначала выберите коммит с поддержкой `KLIO_PREVIEW_SCHEMA` или более новый.
Коммит `8a1f26f` ещё НЕ поддерживает эту настройку: подключать к нему рабочую
базу для тестирования нельзя. В одной операции сохраните новый коммит и
переменные именно тестового стенда:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | Подключение к существующей PostgreSQL |
| `KLIO_PREVIEW_SCHEMA` | `klio_preview_chatkit` |
| `APP_BASE_URL` | `https://sergeitkachuk-cmd-klio-stand-682f.twc1.net` |
| `NEXT_PUBLIC_CHATKIT_DOMAIN_KEY` | Domain key для домена этого стенда |

Последняя переменная нужна при сборке. Остальные читаются при запуске.
Для реальной генерации и подтверждения тестового аккаунта также нужны текущие
настройки AI/relay и почты; без них наличие страницы не доказывает работу чата.
Не переносите `APP_BASE_URL` рабочего сайта: ссылки входа и подтверждения
должны вести на стенд. OAuth требует отдельного разрешённого redirect URL.

Схема создаётся через штатный `db:push` при первом запуске. Все таблицы
приложения получают явно указанную схему; `schemaFilter` ограничивает
обновление только ей. `search_path` подключения не содержит запасного `public`.
Если прав недостаточно, это нужно разбирать по логам приложения, а не
убирать настройку схемы ради запуска.

Подготовка базы передаёт пароль PostgreSQL отдельным полем, поэтому
спецсимволы в строке подключения не ломают разбор URL драйвером. `db:push`
проверяет и код выхода Drizzle, и явное подтверждение `Changes applied` /
`No changes detected`: ошибка с кодом выхода 0 больше не запускает сайт
с неподготовленной базой. В лог попадает только безопасный код ошибки,
без исходной строки подключения. Старые файлы логов могли содержать пароль.

Профили, пароли, сессии, материалы, платежи и публикации клиентов в тестовую
схему не копируются. Для проверки нужен собственный тестовый аккаунт.
Не подключайте клиентские каналы и не отправляйте клиентам тестовые сообщения.

Не переключайте стенд на старый коммит, игнорирующий `KLIO_PREVIEW_SCHEMA`,
при сохранённом подключении к рабочей базе. Настройки основного приложения
не меняйте. Для отдельного пользователя с ограниченными правами или полного
разделения серверных ресурсов потребуется дополнительная настройка хостинга.

## Проверки

`tests/database-preview.test.mjs` запускает настоящий Drizzle push в PGlite:
создаёт рабочие таблицы и контрольные записи, затем тестовую схему, выполняет
запись/редактирование/удаление и повторный push. Проверяется неизменность
рабочих данных, колонок и посторонней схемы. Отдельно проверены неверные имена
схемы и настройки обеих веток подключения PostgreSQL.
